# KFlow 可调三栏、统一产品设计 Agent 与可编辑原型设计规格

日期：2026-07-18  
状态：已通过对话方案评审，待书面规格确认

## 1. 目标

本轮继续强化 KFlow 的 Agent 提效工具定位，不增加固定研发编排或项目管理负担。

目标包括：

- 左侧导航可折叠，给主工作区释放更多空间。
- 右侧辅助栏默认展开得更宽，并允许用户拖动调整宽度。
- 原型可在独立浏览器标签页中预览。
- 用户可在原型中选中具体元素，通过属性修改或自然语言指令进行调整。
- 将需求分析、原型设计与审计、PRD 撰写合并为一个“产品设计 Agent”。
- 产品工作可以从任一环节开始，各环节共享上下文，不形成强制开发链路。

## 2. 设计原则

1. **Agent 优先**：页面核心仍是 Agent 对话、执行过程与产物，不突出流程管理。
2. **环节即模式**：需求分析、原型设计与审计、PRD 撰写是同一 Agent 的工作模式，不是必须依次通过的节点。
3. **用户决定路径**：不做 Agent 协作编排，不限制环节切换，不自动把任务传递到下一 Agent。
4. **上下文连续**：同一需求下的对话、Spec、原型和 PRD 在三个产品模式间共享。
5. **改动可确认**：Agent 对原型的修改先展示差异，由用户确认后应用，并提供撤销入口。

## 3. 方案选择

考虑过三种合并方式：

1. 只合并 Agent 名称，保留三个独立工作区。改动最小，但上下文和体验仍然割裂。
2. 一个产品设计 Agent，内部提供三个可自由切换的模式。上下文统一且用户始终知道当前工作重点。
3. 完全由自然语言自动判断工作环节。最轻，但缺少明确反馈，产物入口不稳定。

采用方案 2。

## 4. 信息架构与工作入口

### 4.1 Agent 列表

原有以下三个 Agent：

- 需求分析 Agent
- 原型设计 Agent
- PRD 撰写 Agent

合并为：

- **产品设计 Agent**：理解业务范围、维护需求 Spec、生成或审计原型、撰写和修改 PRD。

研发和测试 Agent 保持为可直接选择的专业 Agent。界面不展示固定的“产品 → 开发 → 测试”流水线，用户可按实际任务直接进入任一 Agent。

### 4.2 产品工作起点

从新建任务或需求进入产品设计 Agent 后，首先展示三个工作模式：

- 需求分析
- 原型设计与审计
- PRD 撰写

用户任选一个开始。选择结果只决定当前工作区、快捷指令和右侧辅助工具，不改变需求状态，也不要求先完成其他模式。

### 4.3 模式切换

产品设计 Agent 工作区顶部提供紧凑的模式切换器。切换时：

- 保留当前对话；
- 保留已选上下文；
- 保留已生成产物；
- 更新中栏工作区内容；
- 更新右侧辅助工具；
- 不创建新 Agent 会话，不触发自动执行。

底部对话框始终固定在中栏底部。输入的自然语言结合当前模式和当前选中产物或原型元素执行。

## 5. 三栏布局

### 5.1 左侧栏折叠

- 展开宽度沿用约 248px。
- 折叠宽度约 64px。
- 品牌区域提供明确的折叠/展开按钮。
- 折叠时只保留品牌图标、导航图标、最近任务状态点和个人头像。
- 图标提供 tooltip 和可访问名称。
- 折叠状态保存到本地，下次打开恢复。

### 5.2 右侧栏宽度

- 未打开辅助内容时只显示现有窄工具栏。
- 打开辅助内容时默认宽度为 560px，视窗较小时自动收缩。
- 可调范围：最小 420px，最大为窗口宽度的 70%，同时保证中栏保留可用宽度。
- 在右侧面板左边缘提供拖动条；鼠标悬停和拖动时显示清晰状态。
- 双击拖动条恢复默认宽度。
- 调整后的宽度保存到本地。
- 键盘用户可聚焦拖动条，并通过方向键分级调整宽度。

### 5.3 中栏响应

中栏宽度随左右栏变化自动适配。底部对话框不被右侧栏覆盖；当空间不足时，工具栏先收紧或换行，关键工作内容不横向溢出。

## 6. 原型预览与元素级修改

### 6.1 打开方式

原型工作区和右侧原型预览均提供“在浏览器打开”按钮。点击后在新标签页打开独立预览路由，并携带项目、需求、原型版本和检查模式信息。

独立预览页包含：

- 原型页面本体；
- 页面与设备尺寸切换；
- 元素检查模式；
- 选中元素信息；
- 修改和确认区域。

### 6.2 元素选择

- 检查模式开启时，可点击原型中的按钮、输入框、标题、导航项、列表行等可编辑元素。
- 悬停显示轻量描边；点击后显示稳定的选中框。
- 选中信息至少包括元素名称、类型、当前文案、所在页面及关联 Spec。
- 点击空白区域或按 Escape 可取消选择。

### 6.3 混合编辑

选中元素后支持两种互补方式：

1. **属性快速调整**：修改文案、视觉层级、颜色、尺寸和交互状态等演示属性。
2. **自然语言修改**：底部输入诸如“把选中的添加成员按钮改成次要操作”或“将这一行调整为只读状态”。

自然语言输入自动附带当前元素引用，避免用户重复描述目标。

### 6.4 确认机制

- 修改先生成“修改前 / 修改后”摘要。
- 用户点击“应用修改”后更新原型演示状态。
- 提供“撤销本次修改”。
- 本 Demo 只模拟前端状态和交互反馈，不实现真实设计文件持久化或代码生成。

### 6.5 原型审计

“原型设计与审计”是同一模式下的两类动作。Agent 可以：

- 生成或修改原型；
- 检查交互遗漏和不一致；
- 检查企业设计规范冲突；
- 检查 Spec、原型页面和验收标准的覆盖关系；
- 将审计问题定位到具体元素，并允许用户逐条处理。

## 7. 右侧内容适配

右侧栏继续按当前任务和当前产品模式变化：

- 需求分析：问题清单、上下文来源、Spec 摘要。
- 原型设计与审计：页面预览、组件信息、交互与审计问题。
- PRD 撰写：文档预览、PDF 预览、大纲和引用来源。
- 开发 Agent：文件、Diff、问题和运行日志。
- 测试 Agent：用例、失败项、报告和测试证据。
- 日常办公 Agent：仅展示与对应办公任务匹配的工具，不出现代码库和测试资产。

右侧宽度调整属于全局布局能力，右侧具体内容仍由场景决定。

## 8. 状态与数据模型

新增或调整的前端演示状态：

- `isSidebarCollapsed`
- `rightPanelWidth`
- `productWorkMode`: `analysis | prototype | prd`
- `selectedPrototypeElementId`
- `prototypeElementDraft`
- `prototypeChangePreview`

三个旧产品 Agent ID 统一迁移到产品设计 Agent。现有最近任务和会话引用旧 ID 时映射到新 Agent，并保留相应的起始模式。

## 9. 边界与异常

- 小屏幕无法满足最小中栏宽度时，右侧面板回退为覆盖式抽屉。
- 浏览器阻止新标签页时，在当前页面给出可复制的预览链接。
- 当前没有原型产物时，“在浏览器打开”不可用，并引导用户先让产品设计 Agent 生成原型。
- 只读角色可以选择元素和查看属性，但不能应用修改。
- 切换模式或离开页面时，未确认的修改需要保留或放弃提示。

## 10. 验收标准

1. 左侧栏可折叠和恢复，刷新后保持选择。
2. 右侧面板首次展开明显宽于当前版本，并可拖动调整；宽度有上下限且刷新后保持。
3. 新建任务中只出现一个产品设计 Agent，不再出现三个独立产品 Agent。
4. 进入产品设计 Agent 后可任选三个模式开始，并可随时切换。
5. 三个模式共享同一需求对话、上下文和产物，不触发固定流程流转。
6. 原型可在独立浏览器标签页打开。
7. 浏览器预览中可选中特定元素，并显示元素信息和关联 Spec。
8. 用户可通过属性或自然语言修改选中元素，确认后看到演示变化，并可撤销。
9. 右侧内容随产品模式及其他 Agent 类型正确变化。
10. 桌面端主要交互具备键盘可访问性，现有任务、项目、智能资产和个人页面不回归。

## 11. 验证范围

- Reducer 和迁移逻辑单元测试。
- 产品设计 Agent 与模式选择组件测试。
- 左栏折叠及右栏调宽交互测试。
- 原型新标签页链接、元素选择、修改确认和撤销测试。
- 各 Agent / 模式右侧工具解析测试。
- 完整 lint、测试和生产构建。
