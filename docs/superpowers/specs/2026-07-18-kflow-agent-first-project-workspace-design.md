# KFlow Agent-first 项目工作台设计规格

## 1. 背景与目标

当前 Demo 将成员、需求状态、审核门禁和项目资产数量放在项目页首屏，导致产品更像需求或项目管理工具。KFlow 的核心应是 Agent 提效：项目用于划定工作边界，需求用于承载任务目标，产品文档、代码库、记忆库和测试资产用于补充 Agent 上下文。

本次改造目标是：保留现有项目治理能力，但重新排列信息层级，使用户进入项目后首先继续 Agent 工作或选择需求，随后在需求内通过自然语言驱动不同 Agent。

## 2. 已确认的产品原则

- 项目是 Agent 的共享上下文容器，不是管理驾驶舱。
- 项目页采用“双入口 Agent 工作台”：继续最近 Agent 对话，或选择需求进入工作区。
- 点击需求后恢复该需求最后使用的 Agent，用户可随时切换 Agent。
- Agent 自动选择相关上下文，执行前显示来源数量，用户可以增删和锁定。
- 不增加 Agent 编排，不规定产品、研发、测试 Agent 的调用顺序。
- 状态流转和门禁仍然存在，但不占据主视觉；是否切换 Agent、接受产物或调整状态均由用户决定。
- 项目成员可查看项目内全部需求、代码和测试内容；项目角色继续控制编辑权限。
- 继续保留“日常办公”和“系统开发”两类场景。

## 3. 采用方案

采用视觉方案 A“双入口 Agent 工作台”。

项目页第一视觉区显示最近 Agent 工作，第二视觉区显示需求入口。上下文来源显示为紧凑连接条，成员、状态、审核规则和资产维护进入项目设置或右侧抽屉。

未采用的方案：

- “对话即项目”能最快恢复最近工作，但会弱化用户主动选择其他需求的能力。
- “需求 × Agent 启动器”适合首次使用，但连续工作时每次多一步选择，恢复感较弱。

## 4. 信息架构

### 4.1 左侧导航

保留现有导航：新建任务、项目、智能资产、最新任务。项目入口名称不变，进入具体项目后页面标题从管理导向的“项目总览”调整为“项目工作台”。

### 4.2 项目工作台

项目工作台按以下顺序展示：

1. 轻量项目头部。
2. 继续 Agent 工作。
3. 从需求开始。
4. 已连接上下文。
5. 次级项目治理入口。

项目头部只显示项目名称、描述、上下文连接状态和“项目设置”入口。成员数量、资产数量、需求状态配置和审核规则不再作为主要指标展示。

### 4.3 需求 Agent 工作区

点击需求后直接进入该需求最后使用的 Agent 工作区。工作区仍采用左中右三栏：左栏导航，中栏执行，右栏默认收起并承载上下文和产物预览。

中栏始终包含：

- 轻量需求头部。
- 当前 Agent 与切换入口。
- Agent 专属执行区域。
- 固定在底部的自然语言对话框。

## 5. 项目工作台组件

### 5.1 轻量项目头部

头部显示项目名称、描述和“上下文已连接”提示。成员管理、需求状态配置、审核规则和资产维护收进“项目设置”菜单或右侧抽屉。

### 5.2 最近 Agent 工作卡片

首屏展示最近 1–2 项仍可继续的 Agent 工作。每张卡片包含：

- 所属需求。
- Agent 身份和类型。
- 最近一次执行时间。
- 最新产物或结果摘要。
- 待用户确认事项。
- “继续对话”主按钮。

点击后恢复对应需求、Agent、对话和产物上下文。

### 5.3 需求卡片

每份需求展示：

- 编号、标题和目标摘要。
- 最后使用的 Agent。
- 最近工作时间。
- 可调用 Agent 的紧凑头像列表。
- “恢复工作区”主操作。
- 一行弱化的状态或门禁提示。

需求卡片不展示产品、研发、测试负责人列表，不展示多列产物数量，不直接展开状态下拉框。状态修改进入卡片“更多操作”。

### 5.4 已连接上下文条

原产品文档、项目记忆、代码库、测试资产四张卡片合并为一条上下文连接条。它显示来源类型、可用数量和同步状态，不承担主要浏览入口。

点击任一来源后打开右侧抽屉，可查看、搜索、编辑和维护具体内容。原有资产页面继续保留，可从抽屉中的“管理全部”进入。

## 6. Agent 工作区组件

### 6.1 轻量需求头部

头部显示需求标题、项目路径、当前 Agent 和 Spec 版本。需求状态、门禁和负责人使用小标签或“更多”菜单呈现，不持续占据横向工具栏。

### 6.2 Agent 切换器

Agent 切换器是工作区核心控件，支持需求分析、原型设计、PRD 撰写、前端开发、后端开发、代码审查和测试 Agent。切换不受状态或流程顺序限制。

若当前 Agent 存在未确认修订，切换前仍提示用户保留、放弃或返回确认。

### 6.3 Agent 专属执行区

- 需求分析 Agent：范围、约束、依赖、问题和 Spec 建议。
- 原型设计 Agent：页面树、画布、版本和页面预览。
- PRD 撰写 Agent：文档编辑、自然语言修订、版本和 PDF 预览。
- 前后端开发 Agent：开发任务、代码基线、实现记录和 Diff。
- 代码审查 Agent：问题、风险、覆盖结论和代码 Diff。
- 测试 Agent：Spec 关联用例、执行结果和测试报告。

既有工作区功能继续保留，改造重点是减少头部治理信息，强化 Agent 身份、执行内容和用户确认操作。

### 6.4 底部对话框

底部对话框始终可见。它显示当前 Agent、本次上下文数量、权限模式和发送操作。用户通过自然语言继续修改文档、原型、代码或测试产物。

## 7. 自动上下文机制

Agent 根据项目、当前需求、用户指令和 Agent 类型自动选择上下文。执行前在对话框上方显示“本次自动引用 N 项上下文”。

点击后在右侧抽屉按以下类别展示：

- 当前需求与 Spec。
- 产品文档和原型。
- 项目记忆和已确认决策。
- 代码库、分支和关联文件。
- 测试用例、报告和缺陷。

用户可以移除、补充或锁定来源。锁定来源在该需求的后续对话中持续引用，直到用户解除。

Agent 输出需要显示关键引用来源，支持从文档段落、代码变更或测试结论跳转到对应上下文。

## 8. 管理能力降级规则

- 项目设置抽屉：成员、角色、项目设置、需求状态配置、审核规则和全部资产管理。
- 需求更多菜单：调整状态、查看门禁、编辑负责人、归档需求。
- 产物确认：确认 PRD 修订、接受代码变更、确认测试结论等审核动作只在相关产物产生时出现。
- 只读角色：显示“当前角色仅可查看”，继续展示完整内容但禁用编辑操作。

管理功能必须可发现，但不得成为首屏主按钮、主卡片或持续占据需求工作区顶部。

## 9. 交互与状态流

### 9.1 继续最近工作

项目工作台 → 最近 Agent 工作卡片 → 恢复需求与 Agent → 继续对话 → 生成或修订产物 → 用户确认或继续调整。

### 9.2 从需求开始

项目工作台 → 需求卡片 → 恢复最后 Agent → Agent 自动选择上下文 → 用户调整上下文或直接输入指令 → 生成结果。

### 9.3 切换 Agent

需求 Agent 工作区 → Agent 切换器 → 检查未确认修订 → 切换工作区 → 保留同一需求和上下文边界。

任何 Agent 执行完成后只提供“继续调整”“确认结果”和可选的下一步建议，不自动调用另一个 Agent，也不自动修改需求状态。

## 10. 错误与边界状态

- 上下文来源不可用：在来源旁标记失败，允许移除或重试，不阻断其他来源和 Agent 工作。
- Agent 执行失败：保留用户输入和已选上下文，提供重试和切换 Agent。
- 产物生成失败：错误只出现在右侧预览或对应产物卡片，不覆盖整个工作区。
- 未确认修订：离开或切换 Agent 前提示用户确认处理方式。
- 无最近工作：隐藏最近工作区，将“从需求开始”提升为第一视觉区。
- 无需求：展示轻量空状态和“新建需求”入口，同时允许从新建任务页发起项目任务。

## 11. 响应式与可访问性

- 桌面端保持左中右三栏，右栏默认收起。
- 窄屏下最近工作和需求卡片变为单列，右侧抽屉覆盖中栏。
- 管理菜单、上下文抽屉和产物预览均支持 Escape 关闭。
- Agent、需求、上下文来源和主要操作使用明确的可访问名称。
- 状态信息不能只依赖颜色表达。

## 12. 验收标准

- 进入项目后，首屏主要操作是“继续对话”或“恢复工作区”。
- 用户最多两步可以恢复任意需求最后使用的 Agent。
- 需求卡片不再出现直接状态下拉框、负责人列和多列产物统计。
- 四类资产以自动上下文来源出现，不再作为项目首屏四张管理卡片。
- 执行前可查看 Agent 自动选择的上下文，且可以增删和锁定。
- Agent 输出可以查看主要引用来源。
- 状态、门禁、成员和资产维护仍可通过项目设置或更多菜单完成。
- 原型、PRD、PDF、开发任务、代码 Diff、测试用例和测试报告继续可用。
- “日常办公”、智能资产、三栏结构、底部对话框和右侧预览继续可用。
- 不新增 Agent 编排、后端持久化、真实 Git 写入、真实 PDF 转换或外部系统调用。

## 13. 测试策略

- 组件测试：最近 Agent 工作卡片、需求卡片、上下文连接条和项目设置抽屉。
- 状态测试：恢复需求最后 Agent、自动上下文选择、上下文增删和锁定。
- 回归测试：现有 Agent 工作区、办公模式、成员角色编辑、资产查看、Diff、测试报告和 Escape 关闭抽屉。
- 可访问性测试：主导航、Agent 切换器、需求入口、上下文来源和主要按钮的语义名称。
- 生产验证：全量测试、Lint、生产构建和更新后的站点部署。
