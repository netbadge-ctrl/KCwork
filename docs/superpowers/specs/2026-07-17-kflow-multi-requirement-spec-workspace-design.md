# KFlow 多需求项目与 Spec 工作台设计规格

日期：2026-07-17

## 1. 背景与目标

KFlow 是面向企业产品、研发、测试和日常办公的一体化智能工作客户端。现有 Demo 已采用左、中、右三栏结构：左栏负责导航，中栏负责主要工作，右栏默认收起并承载预览、Diff、上下文和测试报告；对话输入固定在中栏底部。

本轮调整把研发模式名称从“代码开发”改为“系统开发”，并将项目从静态资产概览升级为以需求为核心的 Spec-Driven Development 工作空间。

目标如下：

- 一个项目可以包含多份需求，每份需求拥有独立且完整的产品、开发、测试链路。
- 项目成员可查看项目内全部需求、进展、代码和测试资产；项目角色决定编辑能力。
- 需求拥有可自由切换的状态流转，同时保留审核门禁、跳过原因和风险记录。
- 产品文档、项目记忆、代码库、测试资产继续以四张卡片展示，并支持点击查看、编辑和预览。
- 不同 Agent 共用项目与需求上下文，但进入后展示与角色匹配的专属工作台。
- 原型可以在客户端内预览；PRD 可基于原型与上下文生成 PDF，并通过自然语言对话修改。
- 开发任务可关联 Spec、仓库和代码变更，并提供与既有代码的 Diff。
- Spec 是产品、开发和测试共同引用的事实来源，但不引入 Agent 协作编排。

参考方法：[GitHub Spec Kit 对 Spec-Driven Development 的说明](https://github.github.com/spec-kit/concepts/sdd.html)。

## 2. 产品原则

### 2.1 需求是项目中的一级工作对象

项目级资产提供共享上下文，需求负责组织一次具体交付。PRD、原型、开发任务、代码变更、测试用例和报告必须能追溯到所属需求。

### 2.2 状态真实存在，但不成为僵硬流程

系统展示明确的状态和审核结果。所有具备编辑权限的项目成员可以把需求切换到任意状态，也可以回退。未完成门禁不会绝对阻断切换，但系统要求记录原因并显示风险。

### 2.3 Agent 是工作台，不是流程节点

用户按当前目的选择 Agent。系统不自动编排 Agent，也不规定必须依次调用需求分析、原型、PRD、开发和测试 Agent。

### 2.4 人对产物和下一步负责

Agent 生成的 Spec、文档、原型、任务、代码和测试结果都必须可查看、可修改、可比较。用户决定是否保存、确认或进入下一阶段。

### 2.5 项目上下文默认互通

产品、研发和测试成员对同一项目内的需求、进展、代码和测试资产拥有一致的可见性。项目角色仅控制编辑范围，不制造上下文孤岛。

## 3. 全局界面调整

首页模式切换由“日常办公 / 代码开发”调整为“日常办公 / 系统开发”。与研发相关的模式标题、按钮、提示文案和可访问名称统一使用“系统开发”。

三栏结构保持不变：

- 左栏：新建任务、项目、智能资产、最新任务。
- 中栏：当前项目、需求或 Agent 工作台。
- 右栏：默认收起，按需显示成员、资产、页面预览、PDF、代码 Diff、测试报告等辅助内容。
- 底部：固定对话输入框，保留项目、Agent 和附件选择。

## 4. 项目页面

项目页面保持单页结构，不增加内部页签。

### 4.1 项目顶部

顶部包含：

- 项目名称、简介和运行状态。
- 项目成员头像组。
- “管理成员”入口。
- “新建需求”主操作。
- 更多菜单，承载项目设置、需求状态配置和审核规则。

### 4.2 四张共享资产卡片

项目顶部下方继续展示：

1. 产品文档
2. 项目记忆
3. 代码库
4. 测试资产

卡片显示数量、最近更新和简短说明。整张卡片可点击，进入对应资产列表。资产详情默认在右侧抽屉预览，需要连续编辑时再切换中栏为完整编辑页面。

四类资产统一支持：

- 搜索、筛选、新建、查看、编辑和删除。
- 查看版本、更新时间和编辑人。
- 查看被哪些需求引用。
- 在右侧抽屉快速预览。
- 返回项目概览。

各类资产的专属能力：

- 产品文档：原型预览、在线文档、修订差异、PDF 预览和下载。
- 项目记忆：人工确认、失效标记、引用关系和决策来源。
- 代码库：仓库、分支、提交、关联需求和代码 Diff。
- 测试资产：测试用例、计划、执行记录、报告和缺陷。

### 4.3 多需求列表

四张卡片下方展示项目中的全部需求。需求列表支持搜索和按状态筛选，但不采用重型看板作为默认视图。

每条需求显示：

- 需求编号、名称和摘要。
- 当前需求阶段。
- 审核门禁状态与风险提示。
- Spec 完整度和版本。
- 产品、研发、测试负责人。
- 原型、产品文档、开发任务、代码变更和测试用例数量。
- 最近更新人与更新时间。

需求阶段可在列表中直接切换。点击需求主体进入独立需求工作区。

## 5. 成员与权限

点击项目顶部成员区域，在右侧打开成员管理抽屉。支持查看成员、添加成员、修改角色和移除成员。

所有项目成员都可以查看：

- 全部需求及状态历史。
- 全部产品文档和原型。
- 项目记忆和决策记录。
- 已连接代码库、分支、提交和 Diff。
- 全部测试用例、执行结果、报告和缺陷。

项目角色控制编辑范围：

- 项目管理员：编辑全部内容，管理成员和项目配置。
- 产品：编辑需求、业务 Spec、原型和产品文档。
- 研发：编辑技术 Spec、开发任务和代码变更。
- 测试：编辑测试用例、执行记录、报告和缺陷。
- 观察者：只读。

管理员、产品、研发和测试角色都可以自由切换需求阶段。观察者只能查看。

本轮不提供单项资产授权，不为某份需求或某个仓库建立独立可见性规则。

## 6. 需求状态、交付物状态与审核门禁

### 6.1 需求阶段

默认阶段为：

1. 需求澄清
2. 方案设计
3. 待开发
4. 开发中
5. 待测试
6. 测试中
7. 待上线
8. 已完成

项目可增删、重命名和重新排序阶段。具备编辑权限的成员可直接跳转或回退。每次变更记录操作者、时间、原阶段、目标阶段和说明。

### 6.2 交付物状态

交付物状态与需求阶段分离：

- 产品文档：草稿、评审中、已确认、有变更。
- 页面原型：设计中、待确认、已确认、有变更。
- 开发 Spec：生成中、待确认、已确认、有变更。
- 开发任务：未开始、进行中、已完成、有阻塞。
- 测试用例：设计中、待执行、执行中、已完成。
- 测试报告：未生成、生成中、待确认、已确认。

该模型允许表达“需求正在开发，但产品文档出现新变更”等真实情况。

### 6.3 审核门禁

项目可为任意状态切换设置审核门禁。默认示例：

- 进入待开发前：确认 PRD 和原型。
- 进入待测试前：确认代码变更和自测结果。
- 进入待上线前：确认测试报告。

门禁状态包括待审核、已通过、有异议、已跳过。

门禁不绝对阻断状态切换。跳过未完成门禁时，系统要求填写原因，并在需求列表、需求工作区和状态历史中显示风险。

## 7. Spec 包与追溯关系

每份需求拥有持续演进的 Spec 包，包含：

- 背景、目标、范围和非目标。
- 用户故事、业务规则和异常场景。
- 原型页面及交互说明。
- 验收标准。
- 数据、接口、权限和兼容性约束。
- 关联项目记忆、历史决策和代码上下文。
- 开发任务、代码变更和测试结果。

各交付物与 Spec 条目建立引用关系：

- 原型页面引用用户故事和交互规则。
- PRD 章节引用 Spec 条目和原型页面。
- 开发任务引用验收标准和技术约束。
- 代码 Diff 引用开发任务和 Spec 条目。
- 测试用例引用验收标准。

当产品文档或原型被修改时，系统创建新的 Spec 版本，并提示可能受影响的开发任务、代码文件和测试用例。系统不自动回退需求阶段，也不自动触发其他 Agent。

## 8. 需求工作区与 Agent 工作台

需求工作区顶部保持统一，显示项目与需求、当前阶段、审核状态、Spec 版本、成员和 Agent 切换器。底部对话框始终可用。

### 8.1 需求分析 Agent

中栏展示结构化需求画布：用户目标、业务场景、范围、非范围、用户故事、业务规则、异常场景、待澄清问题和验收标准。Agent 通过对话逐项补全，用户可确认、修改或删除每条结论。

### 8.2 原型设计 Agent

中栏展示页面树、页面画布、设备预览切换、交互热点和版本历史。右侧抽屉显示可操作的页面预览、组件属性、设计说明和版本对比。

用户可通过自然语言修改原型，例如移动按钮、增加弹窗或调整页面状态。修改先形成预览版本，确认后保存。

### 8.3 PRD 撰写 Agent

中栏展示文档目录、正文编辑区、引用标记、评论和修订记录。支持：

- 基于已确认原型、Spec 和项目上下文生成 PRD。
- 通过自然语言修改指定章节。
- 查看修改前后差异。
- 确认后保存新版本。
- 生成 PDF，并在右侧抽屉预览和下载。

自然语言修改不直接覆盖已确认版本，而是先生成修订建议。

### 8.4 前端与后端开发 Agent

中栏展示需求 Spec 摘要、开发任务、代码库与分支、基线提交、计划修改文件、实施日志和测试结果。

开发任务可标记未开始、进行中、已完成或有阻塞，并关联：

- Spec 条目和验收标准。
- 目标代码库与分支。
- 预计修改文件与实际修改文件。
- 代码行增删统计。
- 单元测试和构建结果。

右侧抽屉支持统一 Diff、单文件并排 Diff、提交前变更总览、Spec 与代码关联和 AI 修改说明。用户可以接受、继续修改或放弃本次变更。

### 8.5 代码审查 Agent

中栏按严重程度展示需求覆盖、代码质量、安全和兼容性问题。每个问题关联文件、代码行和修复建议，右侧同步显示相关 Diff。

### 8.6 测试 Agent

中栏展示从 Spec 验收标准生成的测试用例、手工与自动化类型、执行状态、缺陷、覆盖关系和测试报告。右侧抽屉显示执行日志、失败截图、接口响应、缺陷详情和报告预览。

### 8.7 日常办公 Agent

日常办公 Agent 不进入需求开发链路。会议纪要、文档、数据分析、演示和邮件 Agent 保持任务对话模式，并按任务类型提供相应编辑器或预览工具。

## 9. 关键交互闭环

本轮 Demo 必须支持：

1. 首页模式名称切换为“日常办公 / 系统开发”。
2. 进入项目并查看四张可点击资产卡片。
3. 打开成员管理，修改成员角色。
4. 查看同一项目中的多份需求。
5. 自由切换需求阶段并展示审核门禁和跳过风险。
6. 点击需求进入需求工作区。
7. 切换原型设计 Agent，查看页面画布与右侧页面预览。
8. 切换 PRD Agent，体验自然语言修订和 PDF 预览。
9. 切换开发 Agent，标记开发任务并查看新旧代码 Diff。
10. 切换测试 Agent，查看用例、执行结果和测试报告。
11. 从四类资产卡片进入资产列表，并打开查看或编辑界面。

## 10. 状态与数据边界

Demo 使用前端内存状态模拟以下实体：

- Project
- ProjectMember
- Requirement
- RequirementStage
- ReviewGate
- SpecPackage 与 SpecVersion
- ProductDocument 与 Prototype
- ProjectMemory
- Repository、Branch 与 CodeChange
- DevelopmentTask
- TestCase、TestRun、TestReport 与 Defect
- AgentWorkspace

所有交互在刷新后可恢复为示例数据。本轮不实现真实代码仓库写入、PDF 文件生成服务、自动化测试执行或企业权限后端。

## 11. 异常与保护

- 切换 Agent 或需求时如存在未确认修改，提示保存、放弃或留在当前页面。
- PDF 生成、代码比较或测试执行失败时，在产物区域展示失败原因和重试入口，不阻断其他操作。
- Spec 发生变更时展示影响提示，但不自动改变需求阶段。
- 跳过审核门禁时要求填写原因，并保留审计记录。
- 未连接代码库时，开发工作台显示连接引导，不伪造 Diff。
- 无编辑权限时，页面保持可见但隐藏或禁用编辑操作，并解释角色限制。

## 12. 验证标准

实现后至少验证：

- “系统开发”文案在首页和任务入口一致。
- 四张资产卡片均可进入对应列表并打开详情。
- 成员角色可在成员管理界面修改。
- 多份需求可独立选择、切换阶段和显示门禁状态。
- 不同 Agent 展示不同中栏工作台。
- 原型、PDF、Diff 和测试报告均可在右侧抽屉预览。
- 底部对话框在所有工作台保持可用。
- 桌面三栏布局和窄屏适配不回归。
- 既有日常办公和智能资产交互继续工作。

## 13. 非目标

本轮不实现：

- Agent 之间的自动协作或任务编排。
- 强制线性开发流程。
- 真实 Git 提交、合并请求或代码写入。
- 真实 PDF 转换服务。
- 真实 CI、自动化测试平台或缺陷系统集成。
- 需求或资产级独立可见性授权。
- 项目成员之外的外部分享。
