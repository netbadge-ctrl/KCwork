# 统一对话任务页设计规格

## 目标

以现有 `TaskView`（参考图 1）作为需求、开发和测试任务的唯一主页面，移除 `RequirementWorkspace`（参考图 2）的独立工作台视觉与入口。客户端始终突出 Agent 对话和执行产物，项目管理信息只作为辅助上下文存在。

## 页面架构

- 项目中点击需求、继续最近任务或新建任务，均进入同一套对话任务页。
- 中栏始终由任务标题、消息流、产物卡片和底部输入框组成，不切换为独立编辑工作台。
- 右侧栏默认收起、支持调宽，根据当前 Agent 或所选产物显示 PRD、原型、代码 Diff、测试结果及上下文。
- Spec 状态、门禁、成员和负责人保留在标题区次要信息或“更多”菜单中，不占用主内容区。

## Agent 与产物

- 产品工作只显示一个“产品设计 Agent”。
- 需求分析、原型设计、PRD 撰写是该 Agent 的开始环节，通过紧凑菜单或自然语言选择，不使用整页页签。
- Agent 结果先进入对话消息流，以产物卡片呈现；点击卡片在右栏查看或编辑。
- 原型支持在右栏编辑，也支持在浏览器打开并选中具体元素修改。
- 系统开发和日常办公继续使用同一页面结构，但右栏内容必须由任务类型与当前 Agent 决定，不能出现无关资产。

## 状态与数据流

- 需求保存自己的对话、当前 Agent、产品开始环节及关联产物。
- 从项目再次进入同一需求时恢复最近对话，而不是打开另一套需求详情页。
- 切换 Agent 或开始环节只改变后续执行方式、快捷操作和右栏内容，不改变页面架构。

## 实施边界

- 删除图 2 的独立工作台入口、顶部三段式页签和工作台主画布。
- 复用现有产物预览、原型编辑、Diff、测试与上下文能力，将入口迁移到对话卡片和右栏。
- 不新增流程编排、管理看板或额外页面层级。

## 验收标准

1. 从项目需求进入后看到图 1 式对话任务页。
2. 页面中不再出现图 2 的“PRD 撰写工作台”或三段式页签。
3. 产品设计 Agent 可从需求分析、原型设计、PRD 撰写任一环节开始。
4. 各类产物从消息卡片进入对应右栏；原型可在浏览器打开。
5. 日常办公、产品设计、开发和测试任务的右栏内容互不混用。
6. 左栏折叠与右栏调宽能力保持可用。

## 验证策略

实施完成后只执行一次必要的自动测试与生产构建。仅当验证失败时修复对应问题并复验，不进行额外重复评审或多轮浏览器检查。
