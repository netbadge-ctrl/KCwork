# KFlow 产品设计 Agent 功能说明与交互规格

日期：2026-07-22  
状态：待书面规格确认

## 1. 产品定位

产品设计 Agent 是 KFlow 系统开发场景中的产品工作入口。它不是需求管理流程，也不是由多个子 Agent 组成的自动编排，而是一个以对话为核心、围绕单个需求持续生成和维护产品产物的专业 Agent。

产品设计 Agent 服务于两类自然工作路径：

- 先形成原型，再基于原型生成或完善 PRD；
- 先形成 PRD，再基于 PRD 生成或完善原型。

系统不要求用户显式选择路径，也不固定执行顺序。Agent 根据当前需求已具备的内容和用户指令判断本次动作。完整产品交付物统一为：原型、PRD、Spec 和验收标准。

## 2. 设计目标

1. 保持对话为产品工作的主要操作入口。
2. 将原型、PRD、Spec 和验收标准组织为同一份“需求包”，避免三个工作模式之间割裂。
3. 允许原型或 PRD 任一先行，并使两者可以相互生成、校正和补充。
4. 让需求天然继承所属项目的知识、记忆和历史产品资产。
5. 支持多页面原型、组件级调整、执行版本和非破坏式回退。
6. 在原型和 PRD 完善且一致后生成正式 Spec 与验收标准。
7. 区分“完整产品交付”和“提前协作”：即使只有 PRD，也允许交给研发或测试。
8. 将管理状态弱化为产物可用性和风险提示，不形成强制流程门禁。

## 3. 核心概念

### 3.1 项目

项目代表一个持续迭代的企业系统。项目提供产品设计所需的共享背景，包括知识库、项目记忆、历史需求、历史原型、业务规范、代码仓库和测试资产。

### 3.2 需求

需求必须归属于一个项目。一份需求对应一个独立对话上下文和一份持续演进的需求包。项目可以包含多份需求，每份需求的产物、版本和下游传递记录彼此独立。

### 3.3 需求包

需求包由四类正式产物组成：

| 产物 | 作用 | 生成条件 | 典型状态 |
| --- | --- | --- | --- |
| 原型 | 表达页面、组件、状态与交互 | 可从对话、历史原型或 PRD 生成 | 未创建、草稿、已确认、有更新 |
| PRD | 表达背景、目标、范围、规则与产品方案 | 可从对话、项目知识或原型生成 | 未创建、草稿、已确认、有更新 |
| Spec | 将已确认产品方案结构化为可供研发消费的规格 | 原型和 PRD 均已确认且无未处理冲突 | 未生成、已生成、需要更新 |
| 验收标准 | 将产品方案转换为可验证条件 | 与正式 Spec 同步生成 | 未生成、已生成、需要更新 |

产物状态只说明内容是否可用，不限制用户切换 Agent、传递上下文或开始研发测试工作。

## 4. 总体操作模型

### 4.1 进入方式

用户从项目中创建需求，或从项目需求列表打开已有需求，然后进入产品设计 Agent。系统自动带入：

- 项目身份和当前需求；
- 项目知识库与共享记忆；
- 当前需求已有的原型、PRD、Spec 和验收标准；
- 可复用的项目历史原型；
- 用户最近一次产品设计对话。

### 4.2 中栏结构

中栏继续沿用统一对话架构：

- 顶部显示需求名称、所属项目和当前产品包状态；
- 中部显示对话、Agent 执行过程和本次生成的产物卡片；
- 底部固定对话框，用自然语言创建、修改、比较、回退或传递产物；
- 不再显示“需求分析／原型设计／PRD 撰写”模式选择器。

需求包状态采用一行轻量摘要，例如“原型 V4 · PRD V3 · Spec 待生成 · 验收标准待生成”。它用于帮助用户理解当前内容，不表现为流程节点或项目看板。

### 4.3 右侧栏结构

产品设计 Agent 的右侧工具入口调整为：

1. 原型
2. PRD
3. 交付检查
4. 版本记录
5. 项目知识

右侧栏默认收起。以下情况自动展开：

- Agent 完成原型生成或修改时，打开原型并定位本次变更页面；
- Agent 完成 PRD 生成或修改时，打开 PRD 并定位本次变更章节；
- 检测到原型与 PRD 冲突时，打开交付检查并定位冲突项；
- 用户要求查看产物、版本、引用依据或传递风险时。

## 5. 产品设计 Agent 的指令理解

Agent 不要求用户先选择工作路径，而是根据指令和现有产物执行对应动作。

示例：

- “参考现有角色管理页面，增加批量调整权限的原型。”
- “根据刚才的原型生成一版 PRD。”
- “先帮我写 PRD，暂时不要生成页面。”
- “用这份 PRD 补齐桌面端和移动端原型。”
- “把成员列表中的角色选择器改为只读，并同步更新 PRD。”
- “检查原型和 PRD 是否一致，生成正式 Spec。”
- “先把当前 PRD 交给后端开发，原型稍后补。”

Agent 每次执行前明确本次读取的上下文，执行后说明更新了哪些产物、页面、组件或章节，以及是否产生新的版本。

## 6. 原型功能说明

### 6.1 原型创建来源

用户可以通过三种来源创建原型：

- 从需求描述和对话直接生成；
- 基于当前 PRD 生成；
- 从项目已有历史原型中选择一个版本，复制到当前需求后进行二次修改。

引用历史原型不会修改原资产。系统在当前需求中创建独立副本，并保留来源项目、来源需求、原型名称和版本信息。

### 6.2 生成后直接预览

每次 Agent 完成原型生成或修改后：

1. 对话中生成原型产物卡片和执行摘要；
2. 右侧原型面板自动展开；
3. 默认展示最新执行版本；
4. 自动切换到本次修改的第一个页面；
5. 对本次修改过的组件提供轻量高亮；
6. 用户无需再次点击“打开预览”。

用户可以关闭右侧栏继续对话，也可以在浏览器新标签页打开完整原型。

### 6.3 多页面原型

一份原型可以包含多个页面。原型面板提供页面树，支持：

- 页面切换；
- 新增页面；
- 复制页面；
- 重命名页面；
- 删除页面；
- 设置起始页面；
- 查看页面之间的跳转关系。

页面树显示本次执行影响标识，方便用户快速定位 Agent 修改过的页面。原型预览支持桌面、平板和移动端尺寸切换。

### 6.4 组件级选择与调整

用户可开启检查模式，选中按钮、输入框、文本、导航项、表格行、卡片、弹窗等组件。选中后显示：

- 组件名称和类型；
- 所属页面；
- 当前文案和关键样式；
- 交互状态和跳转目标；
- 关联的 PRD 章节、Spec 条目和验收标准；
- 最近一次修改版本。

组件调整支持两种方式：

1. 在右侧属性区快速修改文案、颜色、尺寸、状态和交互目标；
2. 通过底部对话框进行自然语言修改。

当用户选中组件后，对话自动携带当前原型版本、页面和组件引用。Agent 只修改用户指定组件及必要的关联内容，不把局部指令扩展为无关的全局改版。

### 6.5 原型版本

以下操作会形成新的原型执行版本：

- Agent 首次生成原型；
- Agent 完成一次多页面或批量修改；
- 用户确认一次组件级修改；
- 用户从历史版本执行回退。

每个版本记录：版本号、执行时间、操作者、来源指令、涉及页面、涉及组件、修改摘要以及关联的 PRD 版本。

用户可以：

- 预览任意历史版本；
- 查看两个版本的页面和组件变化；
- 将历史版本作为新的修改起点；
- 回退到历史版本。

回退采用非破坏式策略。例如当前为 V5，用户选择回退到 V3，系统保留 V4 和 V5，并基于 V3 内容生成新的 V6。页面内容、组件属性和页面跳转关系一并恢复。

## 7. PRD 功能说明

### 7.1 PRD 创建来源

PRD 可以：

- 从需求描述和对话直接生成；
- 基于当前原型生成；
- 基于已有 PRD 继续修改。

生成 PRD 时，Agent 默认读取当前项目知识库、项目记忆、历史需求和适用的业务规范。右侧“项目知识”面板展示本次实际引用的来源，用户可以增删或锁定引用。

### 7.2 编辑与版本

PRD 支持：

- 章节导航和正文查看；
- 直接编辑；
- 通过自然语言修改指定章节；
- 查看修改前后差异；
- 确认或放弃 Agent 修订；
- 版本比较和非破坏式回退；
- 保存到项目产品文档。

原型发生变化时，Agent生成 PRD 修订建议，不自动覆盖已确认版本。用户确认后创建新的 PRD 版本，并记录所对应的原型版本。

## 8. 一致性检查与冲突处理

交付检查持续检查原型与 PRD 的以下关系：

- 页面和功能是否互相覆盖；
- 角色、权限和业务规则是否一致；
- 状态、异常和边界场景是否一致；
- 页面文案和关键交互是否一致；
- 原型跳转是否能够支持 PRD 描述的用户任务。

检测到冲突时，系统不自动选择原型或 PRD 作为唯一真相。用户逐条选择：

- 以原型为准并修订 PRD；
- 以 PRD 为准并修订原型；
- 输入新的处理方式，同时修改两者；
- 暂时保留冲突。

存在未处理冲突时，用户仍可继续修改产物或提前传递 PRD，但不能生成新的正式 Spec 和验收标准。

## 9. Spec 与验收标准

### 9.1 生成条件

正式 Spec 与验收标准在以下条件同时满足后生成：

- 原型已确认；
- PRD 已确认；
- 原型与 PRD 不存在未处理冲突；
- 用户明确要求生成，或确认 Agent 的生成建议。

它们不是产品流程中的强制关卡，也不会阻止用户提前进入研发或测试。

### 9.2 Spec 内容

Spec 至少包含：

- 功能范围与非范围；
- 用户角色与权限；
- 页面、组件和交互状态；
- 业务规则；
- 数据字段和校验要求；
- 异常与边界处理；
- 外部依赖和接口约束；
- 与原型页面、PRD 章节的追溯关系。

### 9.3 验收标准内容

验收标准采用可测试表达，至少包含前置条件、用户动作、预期结果和异常分支。每条标准关联：

- PRD 章节；
- Spec 条目；
- 原型页面和相关组件；
- 后续生成的测试用例。

原型或 PRD 后续发生确认修改时，交付检查将受影响的 Spec 条目和验收标准标记为“需要更新”，但不会自动覆盖已传递给下游的版本。

## 10. 向研发和测试传递

### 10.1 传递入口

用户可以在对话中提出“交给研发”或“交给测试”，也可以在交付检查面板中点击对应操作。系统展示轻量确认面板，不进入复杂的流程编排页面。

### 10.2 允许提前协作

仅有 PRD 时也允许传递。确认面板清楚显示本次包含和缺少的内容，例如：

- 已包含：PRD V2；
- 缺少：原型、Spec、验收标准；
- 风险提示：页面结构、交互细节和可测试条件尚未确认。

风险提示不构成硬门禁。用户确认后即可建立前端、后端或测试 Agent 对话。

### 10.3 上下文快照

传递给下游的是固定版本的上下文快照，包含：

- 项目和需求身份；
- 本次选择的产物及精确版本；
- 实际引用的项目知识；
- 已知缺失项、冲突和风险；
- 传递人和传递时间。

产品产物后续更新时，下游 Agent 显示“产品上下文已有更新”，列出变化内容。由用户决定是否载入新版本。系统不自动覆盖下游上下文，不自动修改代码、测试用例或任务状态。

## 11. 版本与追溯

需求包提供统一版本记录，但原型、PRD、Spec 和验收标准仍保留各自版本号。每次执行记录：

- 用户指令；
- Agent 动作；
- 输入上下文；
- 生成或修改的产物；
- 产物版本；
- 用户确认、放弃或回退结果；
- 传递给下游的快照。

版本记录用于查看、比较、回退和解释 Agent 的修改，不作为项目管理审批流。

## 12. 权限

- 项目成员可以查看项目内全部需求、原型、PRD、Spec、验收标准和版本记录。
- 具备产品内容编辑权限的角色可以生成、修改、确认和回退产品产物。
- 只读角色可以查看页面、组件、差异、版本和引用来源，但不能应用修改或创建传递快照。
- 传递给研发或测试的权限继续遵循项目角色，而非额外的需求级可见性规则。

## 13. 异常与边界

- 项目没有可用知识时，Agent明确提示仅使用本次对话，不虚构项目规则。
- 历史原型不可用时，保留来源信息并提示重新选择，不影响从零生成。
- 原型生成失败时，对话保留本次指令并提供重试，不创建空版本。
- 浏览器阻止新标签页时，提供可复制的原型预览地址。
- 用户关闭自动打开的右侧预览后，同一次执行不重复打开。
- 多页面原型删除被其他页面引用的页面时，先提示受影响跳转。
- 回退不会删除历史版本或已传递的下游快照。
- 原型或 PRD 缺失时，Spec 和验收标准保持未生成，不使用占位内容冒充正式产物。

## 14. 非目标

本轮不实现：

- 多个产品子 Agent 的自动协作或编排；
- 固定的“需求分析 → 原型 → PRD → Spec”流程；
- 以状态看板为中心的需求管理；
- 自动批准产品产物；
- 自动把下游工作切换到最新产品版本；
- 真实后端存储、多人实时协作或外部设计工具写回。

## 15. Demo 功能范围

本次前端 Demo 应完整呈现：

1. 移除产品设计的三个显式模式选择。
2. 在产品对话顶部展示轻量需求包状态。
3. 右侧工具改为原型、PRD、交付检查、版本记录和项目知识。
4. 原型生成后自动打开最新预览。
5. 原型页面树和多页面切换。
6. 组件选择、属性修改和携带组件引用的对话提示。
7. 原型执行版本、版本比较和非破坏式回退演示。
8. PRD 项目知识引用、自然语言修订、版本和差异演示。
9. 原型与 PRD 冲突检查及逐条处理。
10. Spec 与验收标准的生成条件和追溯关系。
11. 仅含 PRD 的研发／测试传递确认和风险提示。
12. 产品上下文更新后由下游用户主动载入新版本的演示反馈。

所有数据和交互保存在当前浏览器会话中，刷新后恢复为 Demo 初始状态。

## 16. 验收标准

1. 用户进入产品设计 Agent 后不再看到三个产品工作模式，也不需要选择先原型或先 PRD。
2. 需求包能够同时表达原型、PRD、Spec 和验收标准的状态与版本。
3. 创建需求时自动关联项目，并可查看本次使用的项目知识。
4. 用户可以从项目历史原型创建当前需求的独立副本。
5. 每次原型生成或修改完成后，右侧自动展示最新结果和本次受影响页面。
6. 一份原型支持多个页面切换、页面管理和页面跳转关系展示。
7. 用户可以选中具体组件，通过属性或对话进行局部修改。
8. 每次确认的原型修改形成执行版本，历史版本可以预览、比较和非破坏式回退。
9. PRD 可以从原型生成，也可以先于原型独立生成，并实际引用项目知识。
10. 原型和 PRD 冲突时，用户可以逐条决定修订方向；冲突未解决时不生成正式 Spec 与验收标准。
11. 原型和 PRD 均确认且一致后，可以生成具有双向追溯关系的 Spec 与验收标准。
12. 只有 PRD 时仍可传递给研发或测试，界面明确展示缺失项和风险但不阻止操作。
13. 下游获得固定版本上下文快照；产品更新后由用户决定是否载入，不自动覆盖。
14. 页面仍以 Agent 对话和产物操作为核心，不出现重型流程看板或自动 Agent 编排。
